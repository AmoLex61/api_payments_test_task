## 01. Повторная отправка после 500 создаёт второй платёж

Severity: High. Риск двойного исполнения платежа после обычного retry.

1. POST `/v1/payments` с базовым телом и `X-Simulate: fail-after-create` → 500.
2. Проверить debug: одна операция уже создана.
3. Повторить POST с тем же ключом и телом, без X-Simulate. Проверить debug.

TO BE: 200, прежний payment_id, count = 1.

AS IS: 201, новый payment_id, count = 2.

## 02. Другое тело с тем же ключом не вызывает 409 код

Severity: High. Клиент получает успешный ответ на запрос с другой суммой,
хотя ответ относится к старому платежу.

1. Создать платёж на 100000 с новым ключом → 201.
2. С тем же ключом и ref отправить amount = 50000. Проверить debug.

TO BE: 409, одна исходная операция на 100000.

AS IS: 200 с прежним ID и суммой 100000; в debug одна операция.

## 03. Принимаются нулевая и отрицательная суммы

Severity: High. Отрицательная сумма попадать в обработку

1. Отправить POST с amount = 0, проверить debug.
2. Повторить с amount = -1 и новым ключом/ref.

TO BE: оба запроса → 422, count = 0. Допущение: сумма платежа должна быть > 0.

AS IS: оба запроса → 201, для каждого ref count = 1; сохранены суммы 0 и -1.
